# Guia de operação

## Onde está cada coisa

| O quê | Onde |
|---|---|
| Site e API | Cloudflare Worker `proxinho`, domínio `proxinho.johnlaff.com` |
| Banco | Cloudflare D1 `proxinho` |
| Fontes das cartas (Beleren, Matrix Bold, Goudy Medieval, MPlantin) | Cloudflare KV `proxinho-fontes` (binding `FONTES`), servidas em `/api/fontes/*.ttf` |
| Dicas das palavras-chave do Arena | O mesmo KV, chave `arena-dicas.json` (não é servida pela API); o workflow "Dados diários" baixa antes do pipeline (ADR 0021) |
| Modelo LaMa e runtimes do ONNX | Assets do site em `/modelos/`, gerados no build por `scripts/modelo.mjs` (baixa do Hugging Face numa revisão fixa, confere o SHA-256 e compacta em gzip): `lama-int4.onnx.gz.0` e `.1`, `ort-webgpu-<versão>.wasm.gz` (placa de vídeo) e `ort-cpu-<versão>.wasm.gz` (CPU) |
| Cartas montadas no servidor | Cloudflare R2 `proxinho-cartas` (binding `CARTAS`, privado), servidas em `/api/cartas/<código>/<chave>.jpg`; gravadas pelo montador em lote (`scripts/montagem`), que roda no workflow "Montagem" com o token OIDC do GitHub ou à mão com o segredo `CARTAS_TOKEN` do Worker; até 6 GB (ADR 0022 e 0023) |
| Atualização dos dados | GitHub Actions, workflow "Dados diários" (04h17 de Brasília) |
| Montagem das cartas | GitHub Actions, workflow "Montagem" (depois de cada push na main que passa na esteira, todo dia às 06h41 de Brasília e à mão; 12 máquinas padrão) |
| Deploy | GitHub Actions, workflow "CI/CD", job "Deploy em produção" (a cada push na main) |
| Logs | Painel da Cloudflare → Workers → proxinho → Logs (observability ligada) |
| Saúde | `GET https://proxinho.johnlaff.com/api/health` → `{ ok, dataUpdatedAt, codigo }` (`codigo`: o resumo do código que desenha no build no ar) |

## Segredos do repositório

`CLOUDFLARE_API_TOKEN` (permissões: Workers Scripts, D1 e Workers Routes do domínio, edição) e `CLOUDFLARE_ACCOUNT_ID`, no ambiente `producao` do GitHub. A montagem no GitHub não pede segredo: o Worker confere o token OIDC do workflow (os números do repositório e do dono ficam em `vars` no `wrangler.jsonc`; ADR 0023). A senha do montador (`CARTAS_TOKEN`), para rodar à mão, é segredo do Worker (`wrangler secret put`) e nunca vai para o GitHub.

## Tarefas comuns

**Atualizar os dados agora:** GitHub → Actions → "Dados diários" → Run workflow.

**Publicar à mão:** sem os segredos acima no GitHub, o "Dados diários" e o deploy do "CI/CD" pulam o passo da Cloudflare (o log avisa) e nada chega à produção. Com `CLOUDFLARE_API_TOKEN` e `CLOUDFLARE_ACCOUNT_ID` no ambiente da máquina, os mesmos passos rodam daqui:
```bash
python3 data/pipeline/build.py                      # dados do dia (~5 min); confira que saíram mais de 30 mil cartas
pnpm exec wrangler d1 migrations apply proxinho --remote
pnpm exec wrangler d1 execute proxinho --remote --file data/out/cards.sql --yes
pnpm build && pnpm exec wrangler deploy             # site e API
curl -s https://proxinho.johnlaff.com/api/health    # dataUpdatedAt de hoje
```

**Regressão visual antes de publicar uma mudança no desenho** (ADR 0027): toda mudança que muda `node scripts/codigo.ts` (o motor, as fontes livres, a entrada da carta) passa por ela antes de publicar.
```bash
pnpm regressao                          # ~630 cartas desta árvore contra origin/main (as da main ficam guardadas)
pnpm regressao -- --sem-rede            # rodada rápida, sem as faces da rede neural
pnpm regressao -- --grupo "sem borda"   # só um grupo da amostra
pnpm regressao -- --base HEAD --ruido   # o ruído: o mesmo código montado duas vezes (deve dar zero; deu zero nas 649 faces em 25/11)
pnpm regressao -- --amostra modais.json # outra lista de impressões (todas as de uma moldura, ao mexer nela)
```
Abra `.regressao/relatorio/index.html`: cada carta que mudou vem com antes, depois, a diferença e o zoom no trecho que mudou. Toda mudança tem de ser a pretendida; a que não for é regressão e segura a publicação. As imagens ficam só em `.regressao/` (fora do Git: o repositório é público). Sem download de navegador, `PW_CHROMIUM_PATH=/caminho/do/chrome`. Cada rodada sobe a página de cada lado num `vite preview` em porta livre e o encerra no fim: um servidor que sobre de uma rodada interrompida não responde no lugar do código novo. Para acrescentar à amostra (uma moldura nova, um erro novo no AGENTS.md), `pnpm data:build` e `python3 scripts/regressao/amostra.py`: as impressões que já estão nela ficam, as citadas no AGENTS.md e nos ADRs como "COLEÇÃO NÚMERO" entram sozinhas, e cada grupo (um novo entra no fim de `GROUPS`) é completado até o tamanho dele. Para sortear tudo de novo, apague `amostra.json` antes, e diga no commit por quê.

**Ícones do app e prévia do link:** `node scripts/marca.mjs` regrava `public/icone-*.png`, `public/apple-touch-icon.png` e `public/og.png` a partir da marca (desenhada no próprio script, com as cores e a fonte do DESIGN.md).

**Voltar o site para a versão anterior:**
```bash
pnpm exec wrangler deployments list
pnpm exec wrangler rollback <id-da-versao>
```

**Rodar uma migração do banco:** crie `migrations/000N_nome.sql`; o deploy aplica sozinho (`wrangler d1 migrations apply proxinho --remote`). Para testar local: `pnpm db:migrate:local`.

**Trocar um arquivo de fonte:** primeiro `python3 scripts/consertar-fontes.py original.ttf arquivo.ttf` (o Chrome recusa fontes com defeito de estrutura e o site cai calado para a fonte livre), depois `pnpm exec wrangler kv key put --remote --binding FONTES mplantin.ttf --path arquivo.ttf` (nomes aceitos em `worker/index.ts`) e aumente o `?v=` das URLs em `src/engine/fonts.ts`, porque o navegador guarda as fontes por 7 dias. Para o ambiente local: `pnpm fonts:local`, com os arquivos em `.fontes-oficiais/` (a regressão também usa uma fonte que estiver lá, antes da do site: é assim que se confere uma fonte nova antes de publicá-la). A `medieval.ttf` (nome da moldura antiga, ADR 0031) sai de `python3 scripts/acentuar-medieval.py Magicmedieval.ttf medieval.ttf`, que monta as letras acentuadas e a cedilha que a MagicMedieval não tem e confere o arquivo no OTS.

**Atualizar as dicas do Arena** (quando o Arena ganha uma mecânica nova): com o Arena atualizado, pegue o `Raw_ClientLocalization_*.mtga` em `MTGA_Data/Downloads/Raw` da pasta do jogo e rode `python3 data/pipeline/build.py --dicas Raw_ClientLocalization_<…>.mtga` (grava `data/cache/arena_dicas.json`, fora do repositório) e `pnpm exec wrangler kv key put --remote --binding FONTES arena-dicas.json --path data/cache/arena_dicas.json`. O próximo "Dados diários" usa as novas. Nunca suba o banco nem o JSON para o repositório.

**Traduzir mais cartas sem texto oficial** (tradução não oficial, ADR 0025): depois de `pnpm data:build`, `python3 data/pipeline/faltam.py --saida faltam.json` lista as linhas que faltam, das cartas mais jogadas para as menos, com até três cartas de exemplo (as folhas de adesivos de Unfinity ficam de fora: não vão no deck e o tipo delas nunca saiu em PT). Cada tradução entra em `data/traducao/linhas.json` (a linha em inglês, exatamente como saiu do script, para o português), no padrão do Arena: antes de traduzir, procure em `data/out/cards.jsonl` as linhas oficiais parecidas e use a mesma frase e o mesmo vocabulário. Subtipo novo vai em `data/traducao/tipos.json`, com o nome tirado de uma carta impressa em PT que o traga no nome, quando há ("Monger" é "Vendilhão", do Vendilhão de Escândalos); o `faltam.py` lista os subtipos sem nome que ainda deixam em inglês uma carta com todas as linhas traduzidas. `pnpm test:data` confere os números e símbolos de cada linha; o `faltam.py` lista, no fim, as linhas que citam um subtipo sem o nome oficial dele ("Wall" é "Barreira" nas cartas oficiais, nunca "Muralha"), e o pipeline avisa quantas são; o log do pipeline diz quantas cartas ganharam a tradução e de onde vieram as linhas. Corrigir uma tradução errada é trocar a linha no mesmo arquivo.

**Transcrever uma impressão em PT que o Scryfall tem só na imagem** (ADR 0026): a impressão vem com `printed_name`, `printed_type_line` e `printed_text` vazios no `data/cache/scryfall_pt.jsonl`, mas com a imagem da carta em PT (`image_status` diferente de `placeholder` e `missing`). Abra a imagem ampliada e copie o que a carta traz escrito em `data/traducao/transcritas.json`, com a chave "coleção/número" do Scryfall: `name` (o nome em inglês), `oracle_text` (o do Oracle de hoje), `printed_name`, `printed_type_line`, `printed_text` (uma linha por habilidade, os símbolos como `{T}` e `{2}{B}`) e `flavor_text` (com as aspas da carta e a assinatura numa linha própria, "— Nome"; `null` sem flavor). Copie como está, com os erros da carta. `pnpm test:data` confere os números e símbolos contra o Oracle; o log do pipeline diz quantas valeram e avisa as que deixaram de valer (o Scryfall passou a trazer o texto, ou a carta mudou de número): essas podem sair do arquivo.

**Cartas guardadas no navegador:** cada publicação que muda o motor (`src/engine`), a entrada da montagem ou as fontes livres muda o resumo `__PROXINHO_BUILD__`, e as prévias e faces do PDF guardadas no IndexedDB de cada pessoa deixam de valer, como as montadas no servidor: a primeira visita depois dela monta no aparelho o que o montador ainda não refez (ADR 0014 e 0022). Mudanças só na interface não mexem nelas.

**O depósito** (`proxinho-cartas`) está ligado desde 21/11/2026. Numa conta nova: ative o R2 no painel da Cloudflare (R2 Object Storage; sem isso a API responde com o erro 10042 e o deploy com o binding falha), crie o depósito (`pnpm exec wrangler r2 bucket create proxinho-cartas`) e publique. Confira com `curl https://proxinho.johnlaff.com/api/cartas`: 401 ("Senha do montador inválida") com o depósito, 503 ("Sem o depósito das cartas montadas") sem ele.

**Montar as cartas no servidor** (ADR 0022 e 0023): o workflow "Montagem" roda sozinho depois de cada push na main e todo dia; depois de uma publicação feita à mão, rode-o em GitHub → Actions → "Montagem" → Run workflow (na main). Ele só monta se o site no ar é do mesmo código, apaga antes as cartas dos códigos velhos e para nos 6 GB do depósito (`--limite-bytes`; a cota grátis do R2, de 10 GB, é da conta inteira). À mão, no mesmo commit que está no ar,

```bash
pnpm montagem:build && pnpm montagem:serve &     # a página do montador em http://localhost:5198
CARTAS_TOKEN=… pnpm montagem -- --enviar          # só o que falta; --escolhidas monta só a arte padrão de cada carta
CARTAS_TOKEN=… pnpm montagem -- --apagar-velhas   # apaga as cartas dos códigos que não estão mais no ar
```

O montador lê a lista de cartas (`/api/cartas/lista`), os dados e as fontes oficiais do site, e confere que o site no ar é deste código, que as fontes oficiais carregaram e que a página tem o mesmo resumo. Monta primeiro as artes que passam pela rede neural (~20 s por face no processador), depois a arte padrão das cartas mais jogadas e depois as outras artes (~1,5 s por face), até o limite; `--partes N --parte K` divide o trabalho entre máquinas e `--prazo-min` para de começar carta nova num prazo. Sem o R2 no ar, `--saida pasta` grava numa pasta e `--enviar-pasta pasta` envia depois. A senha: gere uma nova (`openssl rand -hex 32`), grave no Worker (`pnpm exec wrangler secret put CARTAS_TOKEN`) e use a mesma no montador; nunca no repositório. Enquanto o montador não termina, o site monta no aparelho o que falta, como antes.

**Atualizar o modelo ou o ONNX Runtime:** mude a URL e o SHA-256 em `scripts/modelo.mjs` (ou a versão de `onnxruntime-web`); o runtime leva a versão no nome do arquivo, e um modelo novo deve ganhar nome novo, porque o cache desses arquivos é imutável.

**Atualizações de dependências:** só o Dependabot (`.github/dependabot.yml`), uma vez por semana, agrupado e com 7 dias de espera. O Renovate foi recusado em 17/11/2026 para não haver dois robôs abrindo PRs das mesmas dependências. `@types/node` não recebe versão maior sozinho: sobe junto com o Node do CI (`NODE_VERSION`).

**Consultar o banco:**
```bash
pnpm exec wrangler d1 execute proxinho --remote --command "SELECT count(*) FROM cards"
```

## Quando algo dá errado

| Sintoma | Causa provável | O que fazer |
|---|---|---|
| "CI/CD" falha nos testes de unidade com "Test timed out in 5000ms" (ou outro limite), sem erro de asserção | Um teste do motor (que processa a carta inteira pixel a pixel) passou do limite de tempo na máquina do GitHub, 4 a 6 vezes mais lenta que um computador com a cobertura ligada; não é defeito do código | O limite é `testTimeout` em `vitest.config.ts` (30 s desde 26/11/2026). Rodar a esteira de novo; se o mesmo teste passar perto do limite em `pnpm test:coverage`, acelerar o teste (imagem menor) em vez de só subir o limite |
| "Dados diários" falha em "Confere se o resultado é saudável" | Scryfall ou Untapped mudou formato ou ficou fora | O banco antigo continua no ar. Ver o log do passo "Gera o banco"; ajustar `build.py` |
| Cartas novas do Arena sem português | Untapped ainda não publicou o arquivo novo | Esperar o próximo ciclo; rodar o workflow manualmente |
| Prévias não carregam ("Não carregou") | CDN do Scryfall lento ou fora | Nada a fazer do nosso lado; o botão tenta de novo |
| Importar do Archidekt falha | Deck privado ou API mudou | Testar `GET /api/import?url=...`; ver `worker/importers.ts` |
| "Este link de pedido veio cortado ou alterado" | O app de mensagens cortou o link ou trocou caracteres | Pedir o link de novo (copiado inteiro); o pedido guardado de quem abriu não é apagado. Ver `decodeOrder` em `src/app/order.ts` |
| Pedido guardado não volta ao recarregar | Navegador em modo anônimo, armazenamento do site apagado, ou a API fora do ar na hora de abrir (o pedido continua guardado e volta na próxima visita) | Ver `proxinho:pedido` no `localStorage` (Ferramentas do desenvolvedor → Aplicativo) |
| "Você quis dizer…?" não aparece | `POST /api/sugestoes` falhou (a lista de nomes não encontrados continua, sem sugestões) ou nada parecido passou da nota 6 | Testar `curl -s -X POST https://proxinho.johnlaff.com/api/sugestoes -H 'content-type: application/json' -d '{"names":[{"name":"Sol Rng"}]}'`; ver `src/lib/suggest.ts` |
| Busca vazia por alguns segundos às 04h17 | Recarga do banco (apaga e reinsere) | Esperado; ver ADR 0004 |
| Planeswalker com mancha borrada na caixa de texto | O LaMa não carregou e o motor usou o preenchimento simples | Ver o console do navegador ("preenchimento por rede neural indisponível"); conferir se `/modelos/` foi publicado (o build avisa se o download falhou) |
| Prévia de planeswalker ou de arte sem borda parada no rascunho, sem a parte avançar | A rede neural travou (uma thread do WebAssembly que não sobe, como no Firefox do celular) ou está lenta na CPU | O vigia troca a worker pela do degrau seguinte (o console diz "a rede neural falhou; tentando num modo mais simples"); o limite de cada quadro segue o ritmo medido. Ver `LIMITS`, `MODES`, `nextMode` e `runLimit` em `src/engine/lama.ts` e `pnpm test` (`tests/unit/lama.test.ts`) |
| Arte sem borda sai na original com "Em inglês: o apagador de texto não rodou neste navegador" | A rede neural falhou nos três degraus na página | Esperado: sem ela a caixa sairia borrada. O "Detalhe técnico" da gaveta diz o motivo de cada degrau. Recarregar a página tenta de novo; em outro navegador costuma rodar |
| Chrome ou Safari com placa de vídeo levando dezenas de segundos por quadro | A placa de vídeo falhou e a carta foi para a CPU | Ver o "Detalhe técnico" da gaveta ou o console. Se for `[WebGPU] Kernel … failed`, conferir se a worker importa `onnxruntime-web/webgpu`, não o pacote principal (o JSEP falha no LaMa, ADR 0013) |
| Build com a worker num arquivo só e a preparação do modelo travando | O Vite gerou a worker no formato iife: os runtimes do ONNX ficam embutidos e as threads do WebAssembly não sobem | `worker: { format: "es" }` em `vite.config.ts`; o build tem de gerar `ort.webgpu.bundle.min-*.js` e `ort.wasm.bundle.min-*.js` à parte |
| Carta guardada no navegador com o desenho de antes de uma correção | A chave das cartas guardadas não mudou: o arquivo corrigido não entra no resumo do código que desenha | Pôr o arquivo na lista de `drawingHash` em `scripts/codigo.ts` e publicar de novo; quem já abriu pode limpar os dados do site no navegador. Ver ADR 0014 |
| Primeiro planeswalker demora | Download único do modelo e do runtime (37 MB com placa de vídeo, 33 MB sem) e, sem placa de vídeo, ~7 s por quadro na CPU de um computador | Esperado; a carta aparece antes em rascunho. Ver ADRs 0008 e 0013 |
| Saga sai em inglês com texto em PT disponível | O motor não achou um fio por capítulo (digitalização clara demais, como as promos de pré-estreia), os números dos marcadores ou a barra de tipo no pé, ou o texto não coube nem no corpo 18 | Esperado nas promos de pré-estreia: a versão da coleção sai em PT. Ver `sagaDividers`, `sagaNumerals` e `sagaPlan` em `src/engine/saga.ts` e `pnpm test` (`tests/unit/saga.test.ts`); "Sagas com capítulos que não batem" no log do pipeline lista as que saem como estão já nos dados |
| Invocação de Final Fantasy (criatura Saga) sai em inglês com texto em PT disponível | Sem o lembrete oficial em PT no alto (o "Sacrifique-a após V." dos Knights of Round nunca foi impresso), o motor não achou a barra de tipo entre y 775 e 800 ou o fio do lembrete entre 214 e 228, o número de fios entre os capítulos não bate ou o texto não coube nem no corpo 18; as sem borda saem como estão de propósito | Ver `renderSummon` em `src/engine/render.ts`, `SUMMON` em `src/engine/saga.ts` e `pnpm test` (`tests/unit/saga.test.ts`) |
| Carta de fundir (meld) sai em inglês com texto em PT disponível | É a carta fundida (Brisela, Urza, Planeswalker), que fica na original de propósito, ou uma das sem borda e de vitrine (`meld_supported` no pipeline); na frente, a moldura não passou pelas conferências da carta comum (o motor desistiu) | Ver `meld_supported` e `add_meld_data` em `data/pipeline/build.py` e `pnpm test:data` (`CartasDeFundir`) |
| Carta virada de Kamigawa (flip) sai em inglês com texto em PT disponível | O motor não achou uma das barras de tipo onde a moldura as põe (`flipBar`), a caixa de P/R não bate com o tipo da metade (`flipPtLine`: só a criatura tem a caixa) ou, na moldura atual, o símbolo da coleção; a Erayo, banida no Commander, não tem a tradução não oficial; as fichas de Papel e a de Unhinged saem como estão de propósito (`flip_supported` no pipeline) | Ver `src/engine/flip.ts` e `pnpm test` (`tests/unit/flip.test.ts`) |
| Criatura com Protótipo sai em inglês com texto em PT disponível | O motor não achou a faixa do protótipo, o fio de baixo dela ou uma das abas onde a moldura as põe (`prototypeFrame`: a aba do custo é procurada pelo número de símbolos de `prototype_cost`), ou o texto não começa pelo lembrete do Protótipo (`prototype_text` no pipeline); as de vitrine e sem borda saem como estão de propósito (`prototype_supported`) | Ver `src/engine/prototype.ts` e `pnpm test` (`tests/unit/prototype.test.ts`) |
| Aventura sai em inglês com texto em PT disponível | O motor não achou o livro na imagem (a lombada entre as páginas ou a barra do tipo da aventura), ou a impressão não é da moldura de livro (vitrine, arte estendida, sem borda) | Ver `adventureBook` em `src/engine/adventure.ts` e `pnpm test` (`tests/unit/adventure.test.ts`); as de outro desenho saem como estão de propósito (`adventure_supported` no pipeline) |
| Carta dividida da moldura atual ou da de 2003 sai em inglês com texto em PT disponível | O motor não achou as barras dos nomes e de tipo, as caixas ou a borda preta entre as metades (`splitFrame`, com as medidas da moldura da impressão: `SPLIT` ou `SPLIT_2003`), ou, numa com Fundir, a faixa do pé (`fuseBar`) ou o lembrete oficial nos dados (`add_fuse_reminders`); as de Commander 2016 e as de 2003 com o logotipo da FNM como marca-d'água saem como estão de propósito (`split_frame_ok` no pipeline) | Ver `src/engine/split.ts` e `pnpm test` (`tests/unit/split.test.ts`) |
